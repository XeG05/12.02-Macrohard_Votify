Pasos para ejecutar Votify

Desde la raíz del proyecto (12.02-Macrohard_Votify), en PowerShell.

1. Construir la imagen (solo si cambiaste código)

docker build -t votify .

Si no tocaste nada del código desde la última vez, salta este paso.

2. Levantar el túnel de Cloudflare primero

cloudflared tunnel --url http://localhost:10000

Te dará una URL tipo https://xxxx-xxxx-xxxx-xxxx.trycloudflare.com. Cópiala, la necesitas en el siguiente paso.

Importante: deja esa ventana abierta mientras quieras que el túnel esté activo. Si la cierras o haces Ctrl+C, el túnel se cae.

3. Arrancar el contenedor con la URL del túnel

Pasa la URL como variable de entorno App__Url (doble guión bajo) para que las invitaciones por email se generen con esa URL en vez de localhost:7001:

docker rm -f votify
docker run -d --name votify -p 10000:10000 `
  -e App__Url="https://xxxx-xxxx-xxxx-xxxx.trycloudflare.com" `
  votify
Sustituye https://xxxx-xxxx-xxxx-xxxx.trycloudflare.com por la URL real que te dio cloudflared en el paso 2. Cada vez que relances el túnel, la URL cambia y hay que volver a hacer este paso.
Si te dice que el nombre votify ya existe, el docker rm -f votify lo elimina antes de crearlo de nuevo.

4. Verificar

Abre http://localhost:10000 en tu navegador para confirmar que el contenedor responde, y la URL https://xxxx-xxxx-xxxx-xxxx.trycloudflare.com desde cualquier otro dispositivo para confirmar el acceso externo.

curl http://localhost:10000

Cuando termines

# Detén el túnel: Ctrl+C en la ventana de cloudflared

# Detén el contenedor
docker stop votify

Para volver a arrancarlo sin reconstruir, basta con:

docker start votify
Ojo: docker start reutiliza la App__Url que pusiste al hacer docker run. Si lanzas un túnel nuevo (URL distinta), tienes que volver a docker rm -f votify y docker run con la URL nueva — un docker start no actualizará la URL.
